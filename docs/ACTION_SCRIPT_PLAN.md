## 1. 结论（先读这个）

| 项 | 决议 |
|----|------|
| UI 文案 | **动作脚本** |
| 内部类型 | `type = "script"` → `Action::Script` |
| 语言形态 | **行式 DSL（MeoFlow）**，不是 Lua / JS / Shell |
| 存储 | 存**源码文本**；保存时编译校验；运行时用 **IR（中间表示）** |
| 能力范围 | 编排「原子能力」：输入/粘贴、等待、按键、快捷键、点击、打开应用/链接/文件、Shell、激活应用；可引用已有鼠标宏或其它按钮 |
| 不做（首版） | 图像找图、OCR、复杂条件分支、循环、网络请求、插件市场 |
| 与鼠标宏关系 | **互补**：鼠标宏偏「录制意图」；动作脚本偏「手写编排」；底层可共用步骤 IR |
| 首版 UI | Native 编辑器：多行文本框 + 语法提示 +「试运行」；步骤列表可视化可二期 |

**一句话定位：**

> 给入门用户一套「像说明书一样好读」的短脚本，把 MeoTool 已有的各种动作串成一条可靠流程；给进阶用户足够的原语，而不是再造一个完整 RPA / 编程环境。

## 2. 背景与问题

### 2.1 用户诉求（本方案要回答的）

在编辑按钮里增加一种**可编排**动作类型，希望：

- 用**入门用户易理解**的脚本代码
- 能完成**各种复杂任务编排**
- 现有各类动作都能以脚本形式写出
- 典型例子：输入文字 → 等待 100ms → 按回车 → 再点击某区域……

### 2.2 现状痛点

| 现状 | 限制 |
|------|------|
| 一按钮 = 一个 `Action` | 无法「粘贴后再按 Enter」 |
| `MouseMacro` 仅 click / hotkey / activate / delay | 不能内嵌 `paste_text`、`shell`、`open_url` 等 |
| `Shell` 可写 `&&` / `osascript` | 门槛高、难调试、与 MeoTool 按键/点击能力割裂 |
| Native「编辑按钮」对宏几乎只读 | 复杂流程只能改 TOML，体验差 |

### 2.3 设计目标

| 目标 | 说明 |
|------|------|
| 易理解 | 一行一事；中文命令优先；注释与示例开箱即用 |
| 易编写 | 少标点、少转义；编辑器提供模板与行级错误 |
| 易执行 | 编译一次、顺序执行；失败有中文原因；可试运行 |
| 更通用 | 覆盖现有 Action + 键鼠原语，而不是再加一堆独立类型 |
| 更强 | 在安全上限内支持多步混合流程（建议首版 ≤ 80 步 / ≤ 30s） |
| 合架构 | 仍是「一按钮 → 一个 Action」；不引入常驻脚本运行时 / 市场 |

## 3. 产品定位与边界

### 3.1 适合 MeoTool 的形态

```
用户看到的：短脚本（像备忘录步骤）
       ↓ 编译
引擎看到的：安全 IR 步骤列表
       ↓ 执行
系统看到的：enigo / open / pbcopy / 宏播放器（复用现有能力）
```

### 3.2 与「鼠标宏」的分工

| | 鼠标宏 `mouse_macro` | 动作脚本 `script` |
|--|----------------------|-------------------|
| 创建方式 | 录制 / 捕获点击 | 手写（或模板） |
| 擅长 | 「点这里」的空间意图 | 「先打字再回车」的时间编排 |
| 可读性 | 步骤多为坐标 | 步骤多为自然语言命令 |
| 建议保留 | 是（录制路径不可替代） | 是（编排路径不可替代） |

长期可让鼠标宏「导出为脚本」、脚本里 `播放宏` 引用已有宏，形成统一底层。

### 3.3 明确不做（除非产品方向变更）

- 完整编程语言（变量作用域、函数、闭包、异常体系）
- 图像匹配 / OCR 找按钮作为主路径
- 跨应用超长无人值守后台任务
- 远程脚本市场、任意代码下载执行
- 用 Electron / WebView 做脚本 IDE

> `DESIGN.md` §2.3 原「复杂条件分支 / 图像 RPA」仍成立；本方案用**有边界的线性编排**填补「多步串联」缺口，不推翻该约束。

## 4. 方案比选

### 4.1 候选

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **A. 行式 DSL（MeoFlow）** | 入门友好；可控；易做行号报错；内存极低 | 需自研解析器；表达力受控 | **推荐** |
| B. 可视化步骤列表 only | 零语法 | 复杂流程编辑慢；难复制分享；Native 实现成本高 | 作 DSL 的**二期视图**，不作唯一形态 |
| C. 嵌套 `Action` JSON/TOML 数组 | 与配置同构 | 对入门用户不友好；编辑体验差 | 仅作内部 IR / 导出，不作主编辑面 |
| D. 嵌入 Lua / QuickJS | 通用强 | 内存与攻击面↑；错误难懂；偏离「轻量常驻」 | **不做**（除非未来明确要插件） |
| E. 直接暴露 Shell / AppleScript | 零开发 | 门槛高、危险、难统一键鼠 | 保留现有 `shell`；脚本内可**受控调用**，不作唯一方案 |
| F. 扩展 `MacroStep` 塞满能力 | 改动面小 | 鼠标宏语义被稀释；录制/手写混在一处 | 不推荐作主方案；可共享 IR |

### 4.2 推荐组合

**主路径：A（MeoFlow 源码）→ 编译为 IR → 执行器**  
**辅路径（二期）：B（步骤列表与源码双向同步）**  
**底层：与鼠标宏逐步统一到同一 `FlowStep` IR**

## 5. 推荐方案：MeoFlow 动作脚本

### 5.1 用户心智模型

把按钮想成「一键执行一份小说明书」：

```text
# 在当前输入框提交一句问候
输入 "你好，世界"
等待 100
按键 Enter
```

读起来像中文步骤；写起来几乎不用学编程。

### 5.2 能力分层

```
L0  注释 / 空行 / 等待
L1  键盘：输入、粘贴、按键、快捷键
L2  鼠标：点击（窗口相对 / 屏幕绝对）、可选双击
L3  应用：打开应用 / 链接 / 文件、激活应用
L4  系统：执行命令（复用 Shell，带超时）
L5  组合：播放已有鼠标宏、运行其它按钮（按标签或槽位）
L6+ 进阶（二期+）：简单 if、重复 N 次、变量（剪贴板/前台 App）
```

首版交付 **L0–L4 + L5 中的「播放宏」**；「运行其它按钮」与 L6 放二期。

### 5.3 架构草图

```
┌─────────────────────────────────────────────┐
│  编辑按钮 UI                                │
│  动作类型 = 动作脚本                         │
│  ┌─────────────────────────────────────┐   │
│  │  多行编辑器（源码）  [模板▼] [试运行] │   │
│  └─────────────────────────────────────┘   │
│           │ 保存时 compile()                 │
└───────────┼─────────────────────────────────┘
            ▼
┌─────────────────────────────────────────────┐
│  ScriptCompiler                             │
│  词法/行解析 → FlowProgram(IR) + Diagnostics │
└───────────┼─────────────────────────────────┘
            ▼
┌─────────────────────────────────────────────┐
│  Action::Script { source, program? }        │
│  TOML 持久化以 source 为准                   │
└───────────┼─────────────────────────────────┘
            ▼
┌─────────────────────────────────────────────┐
│  ScriptPlayer / ActionExecutor 分支         │
│  顺序执行 FlowStep；复用 enigo / macro / open│
└─────────────────────────────────────────────┘
```

关键设计：**源码是唯一真源（source of truth）**；IR 可缓存于内存，不必写入 TOML（或可选写入以加速，但要以 source 为准可重建）。

## 6. 语言设计（用户怎么写）

### 6.1 设计原则

1. **一行一步**（一条命令完成一件事）
2. **中文命令为主**，英文别名等价（便于复制国际示例）
3. **字符串用双引号**；支持 `\"` 与 `\n`
4. `#` 开头为注释
5. **大小写不敏感**的命令名；参数按位置或少量具名
6. **禁止**任意表达式求值（没有 `1+2`、没有函数定义）——降低心智与安全风险

### 6.2 最小可行示例

**例 1：输入 → 等待 → 回车**

```text
输入 "hello"
等待 100
按键 Enter
```

**例 2：粘贴邮箱并提交**

```text
粘贴 "meetrice@qq.com"
等待 50
按键 Enter
```

**例 3：点击后快捷键保存**

```text
点击 0.42 0.18
等待 200
快捷键 Cmd+S
```

**例 4：打开应用再粘贴**

```text
打开应用 "Notes"
等待 400
激活应用 "com.apple.Notes"
输入 "来自 MeoTool 的备忘"
```

**例 5：英文别名（与上等价）**

```text
type "hello"
wait 100
key Enter
```

### 6.3 命令一览（首版）

| 中文命令 | 英文别名 | 参数 | 语义 |
|----------|----------|------|------|
| `等待` | `wait` | `毫秒` 或 `100ms` | 休眠 |
| `输入` | `type` / `typewrite` | `"文本"` | 逐字/Unicode 输入（不经剪贴板） |
| `粘贴` | `paste` | `"文本"` | 等价现有 `PasteText`（剪贴板 + Cmd+V） |
| `按键` | `key` / `press` | `Enter` / `Tab` / `Esc` / `Delete` / `Space` / `↑↓←→` … | 单键 |
| `快捷键` | `hotkey` | `Cmd+Shift+P` 等 | 复用现有 Hotkey 解析 |
| `点击` | `click` | `x y` `[左\|右\|中]` `[窗口\|屏幕]` | 默认窗口归一化坐标 |
| `双击` | `double_click` | 同点击 | 连续两次左键 |
| `打开应用` | `open_app` | `"名称或路径或BundleID"` | 复用 `OpenApp` |
| `打开链接` | `open_url` | `"https://…"` | 复用 `OpenUrl` |
| `打开文件` | `open_file` | `"/path"` | 复用 `OpenFile` |
| `执行命令` | `shell` | `"…"` | 复用 `Shell`（同步等待有超时） |
| `激活应用` | `activate` | `"bundle.id"` | 复用宏步骤 |
| `播放宏` | `play_macro` | （无参：播本按钮备份宏）或后续扩展 | 二期可改为引用 |

> 「输入」vs「粘贴」：输入适合短文本、不污染剪贴板；粘贴适合长文本、表情、多行，与现网行为一致。

### 6.4 坐标约定（与鼠标宏对齐）

- 默认：`点击 0.5 0.3` → 目标窗口内容区归一化坐标（0~1）
- 显式屏幕：`点击 1200 800 屏幕` 或 `click 1200 800 screen`
- 按钮：`点击 0.5 0.3 右`

回放前行为与现有宏一致：尽量恢复用户原前台应用焦点（面板触发路径已有此逻辑）。

### 6.5 刻意简化的语法糖

允许：

```text
等待 100
等待 100ms
wait 100
```

不允许（首版直接报错并提示改写）：

```text
等待 100 + 50        # 无表达式
if 前台 == "Safari"  # 无分支
for i in 1..3        # 无循环
```

二期若要「重复」，用显式命令而非通用语言：

```text
重复 3
  按键 Tab
  等待 50
结束
```

### 6.6 报错体验（易理解的关键）

保存或试运行时，错误必须带**行号 + 人话**：

```text
第 3 行：按键名称无法识别「Retrn」。
提示：常用键有 Enter、Tab、Esc、Delete、Space。
```

```text
第 5 行：点击需要两个数字坐标，例如：点击 0.5 0.3
```

不要抛 Rust / 解析器内部术语给用户。

## 7. 数据模型与配置

### 7.1 运行时模型（建议）

```rust
// src/config/model.rs（示意）

pub enum Action {
    // …现有变体…
    /// 动作脚本：源码 + 可选已编译程序（内存缓存）
    Script(ActionScript),
    None,
}

pub struct ActionScript {
    pub source: String,
    /// 保存成功后可缓存；加载配置时由 source 重编译
    pub program: Option<FlowProgram>,
}

pub struct FlowProgram {
    pub steps: Vec<FlowStep>,
    pub estimated_ms: u64,
}

pub enum FlowStep {
    Delay { ms: u64 },
    TypeText { text: String },
    PasteText { text: String },
    Key { key: SpecialKey },
    Hotkey { keys: Vec<Key> },
    Click {
        button: MouseButtonKind,
        x: f32,
        y: f32,
        coord_space: CoordSpace,
        clicks: u8, // 1 or 2
    },
    OpenApp { target: String },
    OpenUrl { url: String },
    OpenFile { path: String },
    Shell { command: String },
    ActivateApp { bundle_id: String },
    PlayMouseMacro { macro_: MouseMacro }, // 或引用 id
}
```

说明：

- `FlowStep` **比** `MacroStep` **更完整**；长期可让 `MacroStep` 成为 `FlowStep` 的子集，或宏播放走同一 Player。
- `SpecialKey` 需覆盖 Enter/Tab/Esc/方向键等（现有 `Key` 枚举偏快捷键修饰，不够用）。

### 7.2 TOML 形态

```toml
[profiles.buttons.action]
type = "script"
source = """
# 提交搜索
输入 "meotool"
等待 100
按键 Enter
"""
```

设计选择：

| 项 | 建议 |
|----|------|
| 是否把 IR 写入 TOML | **否**（避免双源不一致）；启动/保存时编译 |
| 多行字符串 | TOML `"""…"""` |
| 空脚本 | 视为未配置（`is_configured == false`） |

### 7.3 校验与上限（产品护栏）

| 护栏 | 建议值（首版） | 理由 |
|------|----------------|------|
| 最大行数 | 200 行（含空行注释） | 防误粘贴巨文件 |
| 最大步骤数 | 80 | 高于宏的 50，仍可控 |
| 最大总时长 | 30_000 ms | 宏现 10s；编排略放宽 |
| 单次 `等待` 上限 | 10_000 ms | 防误写 `等待 999999` |
| `执行命令` 超时 | 5_000 ms | 避免卡死面板线程 |
| 源码体积 | ≤ 32 KB | 配置膨胀可控 |

超限：编译失败，指出哪条护栏，而不是运行到一半掐断且无说明。

## 8. 执行引擎

### 8.1 调度方式

首版建议：

1. **后台线程 / 专用 queue 执行**（避免卡住 Native UI）
2. 步骤间 `sleep` 可取消（用户再次点同一按钮或全局「停止脚本」——二期）
3. 执行前：与现网一致，尽量把焦点还给目标应用
4. 执行中：面板可短暂「播放中」态（按钮闪烁 / 禁用重入）

同步阻塞在主线程（当前宏的做法）**不推荐**延续到 30s 脚本。

### 8.2 执行伪代码

```text
fn execute_script(script):
  program = script.program or compile(script.source)?
  assert program.within_limits()
  for (i, step) in program.steps:
    if cancelled: break
    match step:
      Delay → sleep
      TypeText → enigo unicode / 逐字
      PasteText → 现有 paste 路径
      Key / Hotkey → enigo
      Click → 复用 macro_player 坐标换算
      Open* / Shell / Activate → 复用 ActionExecutor 内部函数
    on_error → 记录步骤序号与中文原因；可选按钮闪红；中止后续
```

### 8.3 与 `ActionExecutor` 的整合

推荐重构方向（不必一次做完）：

```text
ActionExecutor
  ├─ execute(Action)           // 对外不变
  ├─ execute_flow(FlowProgram) // 新增
  └─ primitives:
        run_hotkey / run_paste / run_open_* / run_shell / run_click …
```

现有 `match Action` 各分支逐步改成调用 primitives；`Script` 与 `MouseMacro` 都走 `execute_flow`。  
这样「脚本能做的 = 引擎原子能力」，不会出现脚本和按钮行为不一致。

### 8.4 试运行

编辑器内「试运行」：

- 编译 → 在**当前前台应用**执行（需提示用户先点到目标窗）
- 不写入配置
- 失败只提示，不关闭编辑器

## 9. 编辑体验（UI）

### 9.1 Native「编辑按钮」（默认路径，优先）

动作类型下拉新增：**动作脚本**。

选中后参数区从单行 `NSTextField` 换成：

```
┌──────────────────────────────────────────────┐
│ 动作类型：[ 动作脚本 ▼ ]                      │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ # 在此编写步骤，一行一件事                 │ │
│ │ 输入 "你好"                                │ │
│ │ 等待 100                                   │ │
│ │ 按键 Enter                                 │ │
│ └──────────────────────────────────────────┘ │
│ [插入模板 ▼]  [语法说明]  [试运行]             │
│ 状态：3 步 · 约 0.2 秒 · 无错误               │
└──────────────────────────────────────────────┘
```

模板建议：

- 输入后回车
- 粘贴后回车
- 点击后快捷键
- 打开应用并输入
- 空白注释骨架

### 9.2 egui 路径

与 Native 对齐：`ActionKind::Script` + 多行编辑 + 同一编译器。  
鼠标宏录制 UI 保留；可提供「将当前宏步骤插入脚本」作为增强。

### 9.3 易编写增强（按优先级）

| 优先级 | 能力 | 说明 |
|--------|------|------|
| P0 | 行号报错 | 编译器 diagnostics |
| P0 | 模板插入 | 降低空白页恐惧 |

## 10. 与现有动作类型的关系

> **编辑 UI 更新（2026-08-31）**：Native / egui「编辑按钮」窗口已改为**仅展示动作脚本编辑器**；原专用类型改为预设快捷按钮。详见 [`BUTTON_EDITOR_SCRIPT_UNIFIED.md`](./BUTTON_EDITOR_SCRIPT_UNIFIED.md)。TOML 运行时类型仍兼容读取；保存时 lazy 升级为 `script`。

### 10.1 兼容策略

| 类型 | 策略 |
|------|------|
| `hotkey` / `paste_text` / … | **保留**。简单需求继续用专用类型，零学习成本 |
| `mouse_macro` | **保留**。录制入口继续服务「点哪里」 |
| `shell` | **保留**。脚本内也可调用，但专用类型更清晰 |
| `script` | **新增**。多步编排的主入口 |

不要强迫用户把所有单步动作都改成脚本。

### 10.2 何时引导用户用脚本

编辑器在用户已选「粘贴文本」时，可轻量提示（非阻断）：

> 需要「粘贴后再按 Enter」？可改用「动作脚本」。

### 10.3 迁移

- 无自动破坏性迁移
- 可选工具：把 `MouseMacro.steps` 渲染为 MeoFlow 文本（导出）
- 旧配置无需改动

## 11. 安全、限制与错误体验

### 11.1 威胁模型（务实）

脚本与现有 `Shell` 类似，本质是**用户本机自动化**。风险来自：

- 用户误写长等待 / 死循环（用上限防）
- 脚本里 `执行命令` 做危险事（与直接选 Shell 相同；需在语法说明中警示）
- 未来若支持分享配置，需警惕「陌生人脚本」（首版不做市场，配置本地）

### 11.2 安全措施

| 措施 | 说明 |
|------|------|
| 无任意代码执行 | DSL ≠ 编程语言 |
| 资源上限 | 步数 / 时长 / 单 wait |
| Shell 隔离 | 仍走现有 `sh -c`；建议同步 + 超时 |
| 重入保护 | 同一脚本执行中忽略重复触发 |
| 权限失败 | 复用辅助功能引导，不静默失败 |

### 11.3 失败策略

- **默认：遇错即停**（Fail-fast），后续步骤不执行
- 日志含 profile / button / step index / 源码行号
- UI：按钮闪红 + 可选简短 toast（若已有通知机制）

首版不做 `忽略错误继续`；若二期需要，用显式前缀：

```text
尝试 点击 0.5 0.3
```

## 13. 验收标准

### 13.1 用户故事

1. 新建按钮 → 动作脚本 → 粘贴示例「输入 / 等待 100 / 按键 Enter」→ 保存 → 在文本框中触发，文字出现并提交。  
2. 脚本含 `点击` 窗口相对坐标，目标窗移动后仍大致点中（与宏同级预期）。  
3. 非法命令保存被拒绝，并指出行号。  
4. `等待 999999` 在编译期被拒绝。  
5. 仅需单步粘贴的用户仍可使用原「粘贴预设文本」，不受影响。

### 13.2 体验

- 从打开编辑器到跑通「输入+回车」≤ 1 分钟（含看模板）。  
- 无编程背景用户能读懂三行示例含义。  
- 脚本执行不导致设置窗/面板永久卡死。

### 13.3 工程

- 解析与执行有单测。  
- 配置 round-trip：source 文本不变义丢失。  
- 内存：不引入脚本 VM；常驻占用无明显跳变（对照现有 baseline 脚本）。

## 14. 决策记录与开放问题

### 14.1 建议默认采纳

| 决策项 | 建议 | 理由 |
|--------|------|------|
| 产品名 | 动作脚本 | 比「编排/RPA」更易懂 |
| 语言 | 中文行式 DSL + 英文别名 | 入门友好且可复制英文示例 |
| 真源 | source 文本 | 易分享、易 diff、易手改 TOML |
| 首版控制流 | 纯顺序 | 守住复杂度；重复/条件二期 |
| 输入实现 | `输入`≠`粘贴` 两命令 | 剪贴板污染可控 |
| UI 优先 | Native 多行编辑 | 默认 UI 路径 |
| 与宏关系 | 并存 + 共享 IR 方向 | 各司其职 |

### 14.2 待评审开放问题

1. **`输入` 是否逐字带间隔？**（建议短文本一次性注入；过长自动分片 + 微小 delay）  
2. **脚本执行中再次点击同一按钮：** 忽略 / 排队 / 取消重跑？建议首版「忽略」。  
3. **是否允许脚本调用 `执行命令`？** 建议允许但模板默认不展示，放在「高级命令」。  
4. **鼠标宏是否在 UI 上降级为「高级」？** 建议否，录制仍是独立刚需。  
5. **SpecialKey 列表完整度：** 首版是否包含 F1–F12、Home/End？建议包含常用编辑键 + F 键。

```text
# 注释

等待 <毫秒>                 # wait 100 / 等待 100ms
输入 "<文本>"               # type "hi"
粘贴 "<文本>"               # paste "hi"

点击 <x> <y> [键] [空间]    # click 0.5 0.3

激活应用 "<bundle.id>"      # activate "com.apple.Safari"

**键名（建议首版）：**  
`Enter` `Return` `Tab` `Esc` `Escape` `Space` `Delete` `Backspace`

`F1`…`F12`

按键 Enter
```
