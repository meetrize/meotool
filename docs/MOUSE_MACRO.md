## 1. 背景与目标

### 1.1 用户诉求

在动作类型中增加「录制鼠标宏」：

- 例如：点击某应用界面上的某个按钮
- 录制一次后，面板按钮可反复执行
- 录制过程中常有大量无效移动与停顿，需要**关键点简化**，得到短、稳、可读的步骤序列

### 1.2 与现有产品的契合点

MeoTool 已具备：

| 已有能力 | 对宏的意义 |
|----------|------------|
| 按前台窗口切换 Profile | 宏天然可绑定「只在某应用下使用」 |
| 触发前恢复目标窗口焦点 | 回放前已有正确前台应用 |
| `Action` 单动作模型 + 编辑器 | 可扩展为新 `type`，复用按钮编辑流程 |
| Accessibility / Input Monitoring | 录制监听与回放注入的权限基础 |
| `CGEventTap` 手势监听 | 可复用事件捕获管线做录制 |
| enigo 键盘模拟 | 可组成「鼠标 + 快捷键」混合步骤 |

### 1.3 目标

| 目标 | 说明 |
|------|------|
| 可复现 | 同一布局下，回放应稳定点到目标控件 |
| 可维护 | 录制结果应是少量关键步骤，而非原始轨迹 |
| 低干扰 | 录制/回放不破坏面板「轻量常驻」体验 |
| 可渐进 | 先做可靠的「点击宏」，再扩展拖拽/混合键鼠 |
| 符合现有架构 | 仍是「一个按钮 → 一个 Action」，不引入完整 RPA 引擎 |

### 1.4 非目标（本方案刻意不做）

- 通用桌面 RPA（条件分支、循环、OCR 找图、图像匹配主路径）
- 跨应用长流程编排器
- 云端宏市场 / 脚本商店
- 像素级鼠标轨迹「原样重播」（对用户价值低，且脆弱）

## 2. 核心结论（先读这个）

**不要把产品做成「完整鼠标轨迹录像机」。**  
更适合 MeoTool 的是：

> **录制意图 → 简化为关键点 → 优先绑定控件，其次绑定窗口相对坐标 → 一键回放**

推荐产品名（UI 文案）：**「鼠标宏」** 或 **「智能点击」**  
内部动作类型：`mouse_macro`

三层能力递进：

```
L1  坐标点击宏（窗口相对坐标 + 关键点简化）     ← 首版必做
L2  控件语义点击（Accessibility 元素定位）      ← 强烈建议紧随其后
L3  混合宏（点击 + 快捷键 + 短等待 + 可选拖拽） ← 增强
```

关键点简化不是「事后压缩文件」，而是**录制结束时的默认产物形态**：用户看到的应是 3～8 步可读步骤，而不是上千个 move 点。

## 3. 产品定位：适合本应用的形态

### 3.1 为什么不能照搬传统宏软件

| 传统宏工具 | MeoTool 更合适的做法 |
|------------|-------------------------|
| 录完整轨迹与实时等待 | 只保留点击/拖拽/按键等意图事件 |
| 绝对屏幕坐标回放 | **窗口相对坐标**（同应用换位置仍可用） |
| 独立宏编辑器很重 | 嵌在现有「动作编辑器」里，保持轻量 |
| 面向任意长流程 | 面向「面板上一键完成一个小操作」 |
| 全局宏库 | 优先挂在 **当前 Profile / 按钮** 上 |

### 3.2 典型场景（本应用真实用法）

1. **设计工具**：点一次「导出」工具栏按钮  
2. **IDE**：点 Run / Debug 旁的小三角（快捷键不好记或不稳定时）  
3. **浏览器 Web 应用**：点固定位置的「发送 / 提交」（无系统快捷键）  
4. **短序列**：点输入框 → 粘贴预设文本 → 点确认（与现有 `paste_text` 组合）

### 3.3 设计原则

1. **意图优先**：用户要的是「点那个按钮」，不是「鼠标画了一条路径」  
2. **默认极简**：录完自动简化；高级用户可展开编辑  
3. **失败可感知**：回放失败要有明确反馈（红闪 + 原因），不能静默点错位置  
4. **权限诚实**：首次使用明确提示辅助功能 / 输入监控用途  
5. **Profile 亲和**：宏默认属于当前配置档，避免跨应用误触发

## 4. 推荐方案：智能点击宏（Smart Click Macro）

### 4.1 动作类型

在现有 `Action` 中新增：

```text
Action::MouseMacro {
    steps: Vec<MacroStep>,
    options: MacroOptions,
}
```

TOML：

```toml
[profiles.buttons.action]
type = "mouse_macro"
# 步骤见 §8
```

动作编辑器下拉新增：**鼠标宏**。

### 4.2 录制捕获什么

| 事件 | 是否保留（简化后） | 说明 |
|------|-------------------|------|
| 左键 / 右键 / 中键 按下与释放 | ✅ | 合并为 click 或保持 down/up（拖拽） |
| 拖拽（down → move → up） | ✅（可选阶段） | 压缩为 start/end 两点 |
| 滚轮 | ⚪ 可选 | 首版可忽略 |
| 键盘（修饰键 + 主键） | ✅（L3） | 与现有 Hotkey 步骤对齐 |
| 纯移动轨迹 | ❌ 默认丢弃 | 仅在「移动到」关键点需要时保留终点 |
| 无操作等待 | ❌ 默认丢弃 | 仅保留用户显式插入或算法判定的必要 delay |

### 4.3 坐标策略（稳定性核心）

录制时同时记录多层信息，回放按优先级尝试：

```
1. 控件定位（AX：role / title / identifier / 路径）  ← 最稳
2. 目标窗口客户区相对坐标（0~1 归一化或 pt）       ← 首版主路径
3. 屏幕绝对坐标（fallback，并警告脆弱）            ← 仅兜底
```

**强烈建议首版就做「相对前台窗口」**，而不是绝对屏幕坐标。  
MeoTool 已有「恢复目标窗口焦点」流水线，相对坐标与之天然契合。

### 4.4 回放流程（接入现有触发链）

```
用户点击面板按钮
  → restore_target_window_focus（已有）
  → 可选：短暂等待窗口稳定（50–120ms）
  → 按 steps 顺序执行
       · move / click / drag / key / delay
  → 成功绿闪 / 失败红闪 + 日志
  → 若 gesture_session && hide_after_button：隐藏面板（已有）
```

注意：回放期间应**忽略面板自身区域**，避免点到 MeoTool；折叠模式更要确保面板不挡目标。

### 4.5 与「只录一次点击」的简化产品形态

对多数用户，完整宏编辑器过重。可提供两种创建方式：

| 模式 | 适合 | 产物 |
|------|------|------|
| **单击捕获** | 点一个按钮 | 1 个 `click` 步骤（最佳默认） |
| **序列录制** | 多步操作 | N 个简化步骤 + 可编辑列表 |

UI 上默认引导「单击捕获」，进阶再「开始录制序列」。

## 5. 关键点简化算法

### 5.1 问题定义

原始录制流：

```
move × 2000 + wait × 若干 + click + move × 800 + click ...
```

目标产物：

```
1. click @ 窗口相对 (0.72, 0.18)   # 工具栏「导出」
2. delay 120ms                     # 仅当算法判定必要时
3. click @ 窗口相对 (0.55, 0.60)   # 对话框「确认」
```

### 5.2 简化流水线（建议固定顺序）

```
原始事件流
  │
  ├─ ① 去抖：合并极短时间内的重复 move
  ├─ ② 丢弃孤立 move（前后无 down/up/click）
  ├─ ③ 点击合成：down+up（同位置、间隔 < click_max_ms）→ Click
  ├─ ④ 拖拽合成：down + 位移超阈 + up → Drag {from,to}
  ├─ ⑤ 等待压缩：
  │      · 删除所有「无事件等待」
  │      · 仅在 click→click 间若间隔 > keep_delay_ms 时，插入有上限的 Delay
  ├─ ⑥ 移动关键点：
  │      · 默认不生成 Move 步骤（click 自带目标点）
  │      · 若需「先悬停再点击」（少数 UI），保留 Hover
  ├─ ⑦ 坐标变换：屏幕点 → 窗口相对 / 尝试绑定 AX 元素
  └─ ⑧ 可读化：生成步骤标题（「点击」「拖拽」「按键」+ 可选备注）
```

### 5.3 关键参数（可配置，给默认值）

| 参数 | 默认建议 | 作用 |
|------|----------|------|
| `move_min_distance_px` | 3 | 小于此位移的 move 忽略 |
| `click_max_ms` | 300 | down→up 视为单击的最大间隔 |
| `drag_min_distance_px` | 8 | 超过则视为拖拽而非点击 |
| `keep_delay_ms` | 200 | 步骤间超过此时长才保留 Delay |
| `max_auto_delay_ms` | 800 | 自动 Delay 上限，防止把发呆录进去 |
| `simplify_level` | `aggressive` | `off` / `normal` / `aggressive` |

**Aggressive（推荐默认）**：删除几乎所有等待与轨迹，只留点击/拖拽/按键。  
用户若回放「太快点丢」，再在步骤间手动加 Delay，或把级别调到 `normal`。

### 5.4 简化预览（必须有）

录制结束后不要静默写入，应展示：

```
已录制原始事件：1,284
简化后步骤：3

1. 左键单击  ·  相对窗口 (72%, 18%)
2. 等待 150ms
3. 左键单击  ·  相对窗口 (55%, 60%)
```

提供操作：

- **采用简化结果**（默认）
- 查看原始（高级）
- 重新录制
- 逐步编辑（改坐标 / 改 delay / 删步骤 / 插入等待）

这是「关键点简化」在交互上的落点：用户必须**看见简化带来的收益**。

## 6. 更好的创意与增强方向

以下按「性价比 / 与 MeoTool 契合度」排序。

### 6.1 ★ 控件级点击（Accessibility Target）——最值得做的增强

不只记坐标，录制点击时查询 AX 树：

- `role`（按钮/链接）
- `title` / `description`
- `identifier`
- 在窗口内的路径或索引

回放时：`找到元素 → AXPress / 点击元素中心`。  
窗口缩放、工具栏微调时，仍可能成功；这比纯坐标宏高一个量级。

失败时自动 fallback 到相对坐标。

### 6.2 ★「单击捕获」作为一等入口

很多用户只需要一步。提供：

> 动作类型选「鼠标宏」→「捕获一次点击」→ 到目标 App 点一下 → 完成

比「开始录制 / 停止录制」心智负担更低，也更符合面板「一键一事」的产品气质。

### 6.3 窗口锚点 + 多显示器稳健性

- 以目标窗口 `CGWindow` bounds 为坐标系  
- 存归一化坐标 `(x/width, y/height)`，窗口尺寸变化时仍大致可用  
- 多显示器下避免「录在屏 A、回放跑到屏 B」的绝对坐标陷阱

### 6.4 与现有动作组合（无需一开始做成万能脚本）

允许宏步骤引用「内置子动作」或引导用户拆按钮：

| 做法 | 说明 |
|------|------|
| 宏内嵌 `hotkey` / `paste_text` 步骤 | 一个按钮完成「点选 + 粘贴」 |
| 两个面板按钮串联 | 更清晰，但多一次点击 |
| Profile 级「触发后附加」 | 后期可做，非首版 |

推荐 L3：宏步骤支持 `key` 与 `paste_text`，把常见办公流收进一键。

### 6.5 回放前「瞄准预览」（Debug 神器）

按住修饰键（如 Option）点击面板按钮：

- 不真正点击，只在目标位置显示准星 0.5s  
- 用于确认宏是否仍对准

对「隔一周再用发现 UI 变了」极其有用。

### 6.6 录制时的安全区与面板隐身

进入录制：

- 面板自动隐藏或缩到角落  
- 屏幕边缘显示细红/主题色录制条 + 「完成 / 取消」全局热键  
- 避免用户把「点击面板」录进宏

### 6.7 「场景校验」轻量护栏

回放前检查：

- 当前前台 Bundle ID 是否与录制时一致（可配置：警告 / 阻止）  
- 目标窗口尺寸变化是否超过阈值（如 20%）→ 提示可能不准

不引入完整条件分支，只做安全护栏。

### 6.8 以后可做但请排后

| 想法 | 为何后置 |
|------|----------|
| 图像/模板匹配找按钮 | 重、慢、脆，和轻量定位冲突 |
| OCR 点文字 | 依赖重，权限与性能成本高 |
| 条件分支 / 循环 | 超出面板产品边界，易做成难用 IDE |
| 轨迹曲线缓动回放 | 看起来酷，对点击类任务无增益 |

## 7. 最佳交互设计

### 7.1 动作编辑器内的信息架构

```
动作类型：[ 鼠标宏 ▼ ]

创建方式：
  (•) 捕获一次点击     ← 默认
  ( ) 录制操作序列

  [ 开始捕获 ]   已有步骤时显示 [ 重新录制 ] [ 编辑步骤 ]

步骤（简化后）：
  1. 单击  相对窗口 72% , 18%     [瞄准] [删]
  2. 等待  150 ms                 [改] [删]
  3. 单击  相对窗口 55% , 60%     [瞄准] [删]
  [ + 插入等待 ]

选项：
  [x] 回放前恢复目标窗口（沿用全局行为，只读提示）
  [x] Bundle ID 不匹配时警告
  简化级别：Aggressive ▼
```

### 7.2 捕获 / 录制态交互（推荐）

#### A. 单击捕获（默认）

1. 用户点「开始捕获」  
2. Toast：**到目标窗口点击一次；Esc 取消；⌘⇧. 强制结束**  
3. MeoTool 隐藏  
4. 监听下一次「主按钮单击」（忽略纯移动）  
5. 记录坐标 + 尝试 AX 绑定 + 自动简化（几乎必为 1 步）  
6. 面板回到编辑器并展示步骤  

#### B. 序列录制

1. 用户点「开始录制」  
2. 屏幕顶栏录制指示：`● REC  00:12  [完成 ⌘⇧.] [取消 Esc]`  
3. 实时事件进入环形缓冲；**UI 可显示实时关键点计数**（不是原始点数）  
4. 结束 → 跑简化流水线 → 预览 diff（原始 N → 步骤 M）→ 确认写入  

#### C. 全局控制热键（建议）

| 热键 | 录制态行为 |
|------|------------|
| `⌘⇧.` | 完成录制 |
| `Esc` | 取消并丢弃 |
| `⌘⇧P`（可选） | 暂停/继续 |

避免与系统「停止录制」类冲突时可在设置中改。

### 7.3 面板主界面交互

- 普通点击按钮 = 回放宏  
- Tooltip 显示：`鼠标宏 · 3 步`  
- 失败：红闪 + 可选状态栏/日志「未找到目标控件 / 坐标越界」  
- 可选：右键按钮 →「瞄准预览」

### 7.4 折叠模式注意点

折叠态触发宏时：

1. 先隐藏/收起面板（若 `hide_after_button`）  
2. 再恢复焦点并回放  
3. 避免回放第一击点到圆形启动器本身  

### 7.5 权限与首次引导

进入「开始捕获」前检查：

- Accessibility（注入点击 / AX）  
- Input Monitoring（监听鼠标）  

不足则复用现有权限页，文案明确：**用于录制与回放鼠标宏，不会上传操作内容**。

### 7.6 交互原则小结

| 原则 | 落地 |
|------|------|
| 默认路径极短 | 优先「捕获一次点击」 |
| 录完即简化 | 预览原始→简化的数量对比 |
| 可编辑但不强迫 | 列表可删改，不强制脚本思维 |
| 可验证 | 瞄准预览 |
| 可撤销 | 重新录制 / Esc 取消 |

## 8. 数据模型与配置

### 8.1 运行时模型（建议）

```rust
enum Action {
    // ...现有
    MouseMacro {
        steps: Vec<MacroStep>,
        options: MacroOptions,
    },
}

struct MacroOptions {
    /// off | normal | aggressive（影响再次简化，已保存步骤不被静默改写）
    simplify_level: SimplifyLevel,
    /// 前台 Bundle ID 与录制不一致时：Allow / Warn / Block
    bundle_mismatch: MismatchPolicy,
    /// 录制时的 bundle id（用于校验）
    recorded_bundle_id: Option<String>,
    /// 回放前额外稳定等待
    pre_delay_ms: u64, // 默认 80
}

enum MacroStep {
    Click {
        button: MouseButton,      // Left/Right/Middle
        target: MacroTarget,
        count: u8,                // 1=单击 2=双击
        modifiers: Vec<Key>,      // 可选
        note: Option<String>,
    },
    Drag {
        button: MouseButton,
        from: MacroTarget,
        to: MacroTarget,
        note: Option<String>,
    },
    Move {
        target: MacroTarget,      // 少用；简化后通常不出现
    },
    Delay {
        ms: u64,
    },
    Key {
        keys: Vec<Key>,           // 复用现有 Key
    },
    PasteText {
        text: String,             // 可选 L3，复用现有能力
    },
}

enum MacroTarget {
    /// 相对目标窗口内容区，归一化 0.0~1.0
    WindowNormalized { x: f32, y: f32 },
    /// 相对窗口 pt（备选）
    WindowPoints { x: f32, y: f32 },
    /// 屏幕绝对坐标（fallback）
    ScreenAbs { x: f32, y: f32 },
    /// Accessibility 控件（L2）
    AxElement {
        role: Option<String>,
        title: Option<String>,
        identifier: Option<String>,
        path: Option<String>,
        /// 找不到控件时的坐标兜底
        fallback: Option<Box<MacroTarget>>,
    },
}
```

### 8.3 文件落地建议

宏步骤直接存在按钮 `action` 内（与现有配置一致），**不要**首版就拆独立宏库文件。

## 9. 执行与平台实现要点

### 9.1 模块划分（建议）

```
src/
  action/
    executor.rs          # match MouseMacro → MacroPlayer
    macro_player.rs      # 逐步执行、delay、错误
  platform/
    macos.rs             # 窗口 bounds、AX 查询/点击
    mouse_monitor.rs     # 扩展：录制用事件回调（与手势复用/分流）
    macro_recorder.rs    # 录制会话、缓冲、热键结束
  macro/
    simplify.rs          # 关键点简化流水线
    target.rs            # 坐标空间转换、多屏
  ui/
    action_editor.rs     # 增加 MouseMacro 编辑 UI
    macro_editor.rs      # 步骤列表 / 捕获按钮 / 预览
```

### 9.2 录制监听

- 复用 `CGEventTap` 能力；与现有右键拖拽手势**分流**：`Recording` 会话期间手势暂停或降级  
- 录制态不把面板点击写入宏（面板隐藏 + 坐标过滤）

### 9.3 回放注入

可选实现路径：

1. **enigo Mouse**（与现有 Keyboard 栈一致，接入快）  
2. **CGEvent 鼠标事件**（与 tap 同源，坐标控制更细）

建议：回放用 CGEvent 或 enigo 均可，但**坐标换算必须统一走「窗口相对 → 屏幕」**，并处理 Retina/pt。

### 9.4 线程与卡顿

- 宏含 Delay 时**不可阻塞 egui UI 线程**  
- 使用后台任务 / async 逐步执行，完成后主线程闪烁反馈  
- 单宏建议硬限制：最长 10s / 最多 50 步（防误录死循环感）

### 9.5 与焦点恢复的时序

```
restore focus → pre_delay → steps...
```

`pre_delay` 默认 80ms，用于消化焦点动画；可在选项里调。

## 11. 风险、边界与不做清单

| 风险 | 缓解 |
|------|------|
| UI 改版导致点偏 | AX 优先；瞄准预览；不匹配警告 |
| 多屏 / 缩放坐标错误 | 统一窗口相对；避免绝对坐标主路径 |
| 录到面板自己 | 录制时隐藏面板 + 坐标过滤 |
| 权限不足 | 复用权限页，失败可诊断 |
| 回放阻塞 UI | 异步逐步执行 |
| 变成「半个 Automator」 | 守住步骤上限与非目标列表 |
| 与右键手势冲突 | 录制会话内暂停手势 |

**明确不做（除非产品方向变更）：**

- 图像匹配主路径  
- 复杂条件分支  
- 无界面后台长任务编排

## 12. 验收标准

### 12.1 用户故事验收

1. 在按钮动作中选择「鼠标宏」→「捕获一次点击」→ 到 Safari 点书签栏某按钮 → 保存后，从 MeoTool 触发可再次点中同一按钮（窗口移动后仍可）。  
2. 录制含大量晃动与停顿的两段点击，结束后预览显示步骤数 ≤ 5，且回放成功。  
3. 无辅助功能权限时，开始捕获会进入权限引导，而不是静默失败。  
4. 折叠模式下触发宏，不会点到圆形启动器本身。

### 12.2 体验验收

- 默认创建路径（单击捕获）从进入到完成 ≤ 3 次有效点击（开始、目标、保存）。  
- 用户能理解「简化后步骤」在表达什么（有中文步骤名，不只是坐标数字）。
