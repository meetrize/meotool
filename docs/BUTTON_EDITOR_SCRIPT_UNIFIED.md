## 1. 结论（先读这个）

| 项 | 决议 |
|----|------|
| 编辑 UI | **移除「动作类型」下拉**；窗口始终展示 MeoFlow 脚本编辑器 |
| 原动作类型 | 变为**预设快捷按钮**（带 Tooltip），点击后**采集参数 → 生成脚本行 → 插入编辑器** |
| 存储（新按钮 / 保存后） | 统一写入 `type = "script"`，`source` 为唯一编辑真源 |
| 旧 TOML | **读兼容、写升级**：打开时把 `hotkey` / `paste_text` / … 转成脚本展示；保存时升级为 `script` |
| 鼠标宏 | 不再作为独立编辑类型；**「录制点击」** 预设走捕获 / 录制 → 导出 MeoFlow；`attached_macro` 仅在迁移过渡期保留 |
| 空动作 | 允许空脚本 = `Action::None`；或仅含注释视为未配置 |

**一句话：**

> 编辑窗口只认「动作脚本」一种形态；原来的类型变成「帮我写一行脚本」的快捷入口，而不是平行的数据模型。

## 2. 背景与动机

### 2.1 现状

Native「编辑按钮」窗口（`button_editor.rs`）包含：

- **动作类型**下拉：`无 / 快捷键 / 打开应用 / … / 鼠标宏 / 动作脚本`
- 非脚本类型：单行 **动作参数** 文本框
- 脚本类型：多行编辑器 + 模板下拉 + 捕获 / 试运行

动作脚本（MeoFlow）已能表达全部原子能力（见 `ACTION_SCRIPT_PLAN.md` §6.3）。继续维护两套 UI 导致：

| 问题 | 说明 |
|------|------|
| 认知分裂 | 用户不知道选「粘贴文本」还是写 `粘贴 "…"` |
| 无法串联 | 选专用类型后无法在同一按钮里「粘贴再回车」 |
| 代码重复 | `action_to_fields` / `fields_to_action` 与脚本编辑器并行 |
| 升级引导弱 | §10.2 的「轻量提示换脚本」不如直接统一入口 |

### 2.2 产品判断

自 Phase 1–3 动作脚本落地后，**专用类型在编辑层的价值主要是「零语法门槛的参数表单」**，而非独立的运行时语义。  
因此：**保留表单的便捷性，去掉类型的平行分支**——表单只作为「生成脚本片段」的向导。

## 3. 设计目标与非目标

### 3.1 目标

| 目标 | 说明 |
|------|------|
| 单一编辑面 | 用户始终看到同一块脚本区，减少模式切换 |
| 低门槛 | 不懂语法的用户点预设 + 填参数即可 |
| 可进阶 | 熟用户直接改源码；预设只负责插入 |
| 可串联 | 任意预设插入后可继续追加步骤 |
| 智能采集 | 按参数类型自动弹出文件选择、快捷键录制、点击捕获等 |
| 兼容旧配置 | 打开旧按钮不丢数据；保存可选静默升级 |

### 3.2 非目标（本方案不做）

- 删除运行时 `Action::Hotkey` 等枚举（执行器仍可直跑，供未迁移配置使用）
- 强制批量迁移用户 TOML（可提供独立迁移工具，默认 lazy upgrade）
- 可视化步骤列表作为主编辑面（仍属二期增强）
- 预设市场 / 云端脚本库

## 4. 用户心智模型

```
按钮 = 一份可执行的小说明书（MeoFlow 脚本）

快捷预设 = 「帮我写进说明书里的某一段」
           不是另一种按钮类型

捕获 / 浏览 / 录制 = 替我把参数填进脚本，而不是填进隐藏的表单字段
```

**典型路径：**

1. **纯新手**：点「粘贴文本」→ 输入邮箱 → 编辑器出现 `粘贴 "a@b.com"` → 完成  
2. **稍进阶**：点「粘贴文本」填邮箱 → 再点「输入后回车」模板 → 合并成两步流  
3. **熟手**：空白脚本直接写；预设仅用于插入 `点击` 坐标

### 5.2 控件说明

| 区域 | 行为 |
|------|------|
| **动作脚本**标题 | 取代原「动作类型」标签；强调唯一编辑对象 |
| **快捷添加** | 8 个预设，每个对应原一种专用类型（除「无」） |
| **流程模板** | 沿用现有 `SCRIPT_TEMPLATES` 多行片段 |
| **工具** | 保留现有捕获 / 试运行；「语法说明」打开轻量帮助（NSAlert 或侧 sheet） |
| **状态 / 预览** | 沿用 `compile()` + `step_preview_label` |

### 5.3 预设按钮视觉

- 样式：`NSButton` 小胶囊或 icon+文字，**两行网格**（快捷添加 4+4，模板 2×2）
- **Tooltip 必填**（见 §11）
- Hover：系统默认；可选浅色底区分「单行预设」与「多行模板」（模板用 `NSBox` 分组标题「流程模板」）

### 5.4 移除的控件

- `action_kind`（NSPopUpButton）
- `payload_label` + `action_payload`（单行参数）
- `browse_file`（并入「打开文件」预设向导）
- `script_template` 下拉（改为可见模板按钮）
- `script_export_macro` 独立按钮（合并进「录制点击」完成流或右键菜单）

## 6. 预设体系

### 6.1 预设定义（数据结构）

建议在 `src/config/script_presets.rs`（新模块）集中定义：

```rust
pub enum PresetParamKind {
    None,              // 直接插入，无参
    HotkeyCapture,     // 快捷键录制
    Text { multiline: bool, placeholder: &'static str },
    Url,               // URL 校验
    ShellCommand,      // 多行命令
    OpenFilePanel,     // NSOpenPanel 选文件
    OpenAppPanel,      // .app 选择 或 捕获应用窗口
    ClickCapture,      // 一次点击 → 坐标行
    MacroRecord,       // 进入宏录制 → 结束导出多行
}

pub struct ScriptPreset {
    pub id: &'static str,
    pub label: &'static str,
    pub tooltip: &'static str,
    pub icon: Option<&'static str>,  // SF Symbol 名或内置 icon key
    pub param: PresetParamKind,
    /// 静态模板；`{0}` `{1}` 为占位符，或由 builder 函数生成
    pub template: PresetTemplate,
    pub group: PresetGroup,  // Quick | Flow
}

pub enum PresetTemplate {
    Static(&'static str),
    Fn(fn(&PresetParams) -> String),
}
```

### 6.2 快捷添加（原专用类型映射）

| ID | 标签 | 对应原类型 | 默认脚本形态 |
|----|------|------------|--------------|
| `hotkey` | 快捷键 | `hotkey` | `快捷键 {keys}` |
| `open_app` | 打开应用 | `open_app` | `打开应用 "{target}"` |
| `open_url` | 打开链接 | `open_url` | `打开链接 "{url}"` |
| `open_file` | 打开文件 | `open_file` | `打开文件 "{path}"` |
| `paste` | 粘贴文本 | `paste_text` | `粘贴 "{text}"` |
| `shell` | 执行命令 | `shell` | `执行命令 "{cmd}"` |
| `click_once` | 点击一次 | 宏单步 | `点击 {x} {y}` |
| `record_clicks` | 录制点击 | `mouse_macro` | 多行 `点击` / `等待` / `快捷键` … |

### 6.3 流程模板（沿用现有）

| ID | 标签 | 说明 |
|----|------|------|
| `type_enter` | 输入后回车 | 输入 + 等待 + Enter |
| `paste_enter` | 粘贴后回车 | 粘贴 + 等待 + Enter |
| `click_hotkey` | 点击后快捷键 | 点击 + 等待 + 快捷键（快捷键需二次采集） |
| `open_app_type` | 打开应用并输入 | 打开应用 + 等待 + 输入（打开应用、文本需采集） |

**复合模板参数策略：**

- 模板内若含占位符（如 `{app}` `{text}` `{hotkey}`），点击后按顺序弹出 mini-wizard（见 §7.4）
- 若用户取消任一步，整个模板插入 abort，不写入半成脚本

## 7. 参数采集与脚本生成

### 7.1 采集方式一览

| PresetParamKind | UI 实现 | 复用现有能力 |
|-----------------|---------|--------------|
| `HotkeyCapture` | 模态 sheet：「请按下快捷键」+ 监听 | `HotkeyRecorder` / Native 全局键监听 |
| `Text` | `NSAlert` accessory view 或 small NSPanel + NSTextField / NSTextView | 新建 `text_prompt_panel` |
| `Url` | 同上 + `http(s)://` 前缀提示；空则 abort | — |
| `ShellCommand` | 多行 NSTextView sheet | — |
| `OpenFilePanel` | `NSOpenPanel` | 现有 `pick_open_file_path` |
| `OpenAppPanel` | 二选一：**浏览 .app**（NSOpenPanel）或 **捕获应用**（`StartAppPick`） | scope 区已有 App pick |
| `ClickCapture` | 隐藏编辑窗 → `StartScriptClickCapture` | 已实现 |
| `MacroRecord` | 隐藏编辑窗 → 宏录制 UI → `macro_to_meoflow` | 已实现 |

### 7.2 各预设交互流程

#### 快捷键

1. 用户点「快捷键」
2. Sheet：`按下要模拟的快捷键组合` [取消]
3. 录制成功 → 插入 `快捷键 Cmd+Shift+P\n`（光标处或末尾，见 §8）
4. 失败 / Esc → 无变更

#### 打开应用

1. Sheet 两按钮：`选择 .app 文件…` | `点选正在运行的窗口…`
2. 文件 → 解析为应用名或路径，优先 Bundle ID
3. 点选 → 复用 `StartAppPick`，回调写入 `打开应用 "Notes"` 或 `打开应用 "com.apple.Notes"`
4. 插入一行

#### 打开链接

1. Sheet：单行 URL 输入，placeholder `https://`
2. Trim；若不含 `://` 可自动补 `https://`（可选，需提示）
3. 插入 `打开链接 "…"\n`

#### 打开文件

1. 直接 `NSOpenPanel`（无中间 sheet）
2. 路径经 `path_for_config` 写成 `~/…`
3. 插入 `打开文件 "…"\n`

#### 粘贴文本

1. Sheet：多行文本框（支持粘贴、换行）
2. 字符串转义 `\"` `\n`
3. 插入 `粘贴 "…"\n`

#### 执行命令

1. Sheet：多行命令框 + 警示文案「与 Shell 相同权限，请谨慎」
2. 单行命令也允许
3. 插入 `执行命令 "…"\n`（内部转义）

#### 点击一次

1. 等同工具栏「捕获点击」：状态行提示 → 目标窗口点一下
2. 插入 `点击 0.4231 0.1822\n`

#### 录制点击

1. 进入现有宏序列录制（`StartSequence` / 完成 / 取消）
2. 结束时 `macro_to_meoflow` → **追加**多行到脚本
3. `attached_macro` 写入 `ActionScript.attached_macro`（供 `播放宏` 与回放优化，过渡期）

### 7.3 字符串转义规则

生成脚本时统一走 `escape_meoflow_string(s: &str) -> String`：

- `\` → `\\`
- `"` → `\"`
- 换行 → `\n`（粘贴、shell 多行）

### 7.4 复合模板 Mini-Wizard

以「点击后快捷键」为例：

```
Step 1/2  捕获点击位置     [开始捕获]  → 得到 x,y
Step 2/2  录制快捷键       [录制]      → 得到 keys
→ 生成：
  点击 0.42 0.18
  等待 200
  快捷键 Cmd+S
```

以「打开应用并输入」为例：

```
Step 1/2  选择应用         [浏览 / 点选]
Step 2/2  输入文字         [文本框]
→ 生成三行（含等待 400）
```

Wizard 用小型分步 NSPanel，带进度 `1/2`；**Back** 可回退上一步已采集值。

## 8. 插入策略与冲突处理

### 8.1 插入位置

| 条件 | 行为 |
|------|------|
| NSTextView 有选区 / 光标 | 在光标处插入（保留 Undo） |
| 无焦点 | 追加到文末 |
| 插入前无 trailing newline | 先补 `\n` 再插入（与现有 `append_script_line` 一致） |

### 8.2 非空脚本时点预设

| 预设类型 | 建议 |
|----------|------|
| 单行快捷 | **直接插入**，不确认（用户可 Undo） |
| 多行流程模板 | 若脚本非空且非仅注释，弹轻量确认：「追加到文末」/「替换全部」/「取消」 |
| 录制点击 | 始终追加 |

### 8.3 「清空脚本」

不提供显式「无」类型。用户删光文本 = 无动作。  
可选：长按「语法说明」旁「重置」→ 清空并写入注释骨架。

## 9. 打开 / 加载 / 保存行为

### 9.1 打开按钮（`load`）

```
Action 变体
    │
    ├─ Script ──────────────► 直接显示 source
    │
    ├─ None ───────────────► 空或注释骨架
    │
    └─ 其它 legacy ─────────► action_to_meoflow(action)
                              显示于编辑器（不立即写盘）
                              标记 draft.was_legacy = true（UI 可选提示）
```

**`action_to_meoflow`（新函数，放 `script_compiler.rs` 或 `action/legacy.rs`）：**

| 输入 | 输出示例 |
|------|----------|
| `Hotkey(keys)` | `快捷键 Cmd+S` |
| `OpenApp { target }` | `打开应用 "{target}"` |
| `Shell { command }` | `执行命令 "{escaped}"` |
| `OpenUrl { url }` | `打开链接 "{url}"` |
| `OpenFile { path }` | `打开文件 "{path}"` |
| `PasteText { text }` | `粘贴 "{text}"` |
| `MouseMacro(m)` | `macro_to_meoflow(m)` + 保留 `attached_macro` |

### 9.2 保存（`collect`）

1. 脚本 trim 为空 → `Action::None`
2. 非空 → `compile(source)` 必须通过，否则禁止保存并定位错误
3. 写入 `Action::Script { source, program, attached_macro }`
4. **不再**根据下拉写 `hotkey` / `paste_text` 等

### 9.3 首次保存升级提示

若 `draft.was_legacy` 且用户修改后保存，可 Toast / 状态行一次：

> 已升级为动作脚本格式，下次将直接编辑脚本。

不阻断操作。

## 10. 与旧配置兼容

### 10.1 策略矩阵

| 层级 | 策略 |
|------|------|
| TOML 读取 | 不变，仍解析 `type = "hotkey"` 等 |
| 编辑 UI | 打开时转换为脚本展示 |
| TOML 写入 | 保存后写 `type = "script"` |
| 执行器 | 不变；未打开过的旧按钮仍直跑 legacy `Action` |
| 批量迁移 | 可选 CLI / 菜单「将全部按钮升级为脚本」（独立任务） |

### 10.2 attached_macro 过渡

- 从 `MouseMacro` 打开：`attached_macro = Some(m)`，源码由 `macro_to_meoflow` 生成
- 用户纯手写点击行后：可不 attached
- 长期：`播放宏` 仅在有 attached 时可用；或二期去掉 attached，完全源码化

### 10.3 与 ACTION_SCRIPT_PLAN §10 的差异

原方案：「专用类型保留，不强迫迁移」。  
本方案：**编辑层统一**，**存储层 lazy 升级**，执行层双轨只作过渡。  
理由：MeoFlow 已覆盖全部能力；双轨 UI 维护成本高于执行层兼容成本。

## 11. 文案与 Tooltip 表

### 11.1 快捷添加 Tooltip

| 按钮 | Tooltip |
|------|---------|
| 快捷键 | 录制一组按键并插入「快捷键 Cmd+…」行。不会切换当前前台应用。 |
| 打开应用 | 选择 .app 或点选窗口，插入「打开应用 "…"」行。 |
| 打开链接 | 输入网址，用默认浏览器打开。 |
| 打开文件 | 选择本地文件或文件夹，用系统默认应用打开。 |
| 粘贴文本 | 将预设文字写入剪贴板并模拟粘贴（Cmd+V）。适合长文本与 emoji。 |
| 执行命令 | 运行一条 Shell 命令（与旧「执行命令」相同权限）。 |
| 点击一次 | 到目标窗口点一下，插入窗口相对坐标「点击 x y」。 |
| 录制点击 | 连续录制多次点击、按键与等待，结束追加多行脚本。 |

### 11.2 流程模板 Tooltip

## 12. 边界情况与错误体验

| 场景 | 处理 |
|------|------|
| 编译失败点保存 | 弹窗展示行号 + `primary_display()`，不关闭编辑器 |
| 录制中关闭窗口 | 取消录制，不保存 |
| 捕获点击超时 | 30s 无点击 → 恢复编辑窗，状态行提示 |
| 快捷键录制冲突 | 与全局热键冲突时提示，不插入 |
| 极长粘贴文本 | 超 32KB 源码上限时保存失败，提示缩短 |
| legacy 宏仅 TOML 可编辑 | 打开时 `macro_to_meoflow`；若转换失败提示打开配置文件 |
| 空脚本启用按钮 | 允许保存；运行时等同 None |
